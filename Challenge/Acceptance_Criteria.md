## 2. Design.md：数学与算法验收

### 2.1 无条件辅助能量耗散

基本版本必须有严格证明。证明须写明辅助变量定义、对应辅助能量、初始化、完整离散更新、数学假设、可解性及状态有效范围。对现行 ESAV，明确的辅助量是 $4E^0\ln r$；若另提辅助定义，说明新量与定义的关系。

“无条件”指在所列数学假设下，对任意正学习率成立。不能依赖学习率上界、回溯后接受条件或数值观察。必须证明所提交完整基本算法的辅助能量非增，包含其 Relax 更新；不能只证明一个未实际采用的中间步骤。

真实目标耗散不能替代辅助能量证明。仅证明加入动能后的组合量耗散，也不能作为基本版本满足本项的依据。先完成满足硬约束的基本版本；动量或其他扩展分别列出耗散对象、保证和限制。

### 2.2 方案可行性

算法应写清初始化、更新公式、所需参数和必要条件，使独立实现成为可能。说明相对冻结基线的变化、设计理由和已知限制，区分证明与实验观察。

只要求交付一个可行方案。不要求同时完成基础、PB 和动量版本，也不要求逐项解释历史现象、完整收敛理论、误差分析或穷举失败情形。额外分析由模型按方案需要决定；无条件辅助能量耗散的严格证明仍是硬性要求，不能替代为其他性质。

允许批评当前 ESAV，但必须同时给出详细理由、实际结果、合理替代设计及对应 Relax，并满足本题硬性要求。只批评、不交付替代设计与实验结果，不接受。负面结果可以支持分析，不能代替必须完成的交付。

## 3. Result.md：实际实验与效果验收

必须展示实际执行的本地实验，范围仅为 Background 中的二次型和非线性回归。不得用计划或历史表格冒充新方案结果。模型自行设计科学合理的超参数、控制变量、预算、停止和失败规则，并说明依据；本范围内的独立本地实验无需再次等待额外批准。

### 3.1 控制变量与计算成本

- 固定问题定义、目标归一化、数据、初始化、分组、精度和设备。先在同配置下比较，再单独改变学习率控制或其他组件。
- 对照包括未 Relax ESAV、现有 Relax-ESAV、同级 SAV/Relax-SAV、SGD、AdamW。副本保持冻结基线，参数与控制器的选择另行记录，不偷换算法。
- 自行选择合理的预算和效果指标，并说明计算成本，使比较公平、结论可核查。不强制同时完成等更新次数、等耗时和阈值达成三套比较。
- 记录目标/梯度求值、分量求导、求解、内存、搜索和调参成本。缓存或求解优化给基线相同机会，区分数学改进与工程节省。稳定加速比须有可靠计时依据，不能仅用一次计时支持。
- 实验设置由模型科学设计，不要求逐组重做历史实验；不得只报告有利结果。

单个实验内部对齐预算与控制变量。各模型可以科学设计不同实验预算，但跨模型比较必须披露成本和执行条件，不假定预算相同。不要求新方案在所有问题或指标上获胜；采用判断区分理论可行性、数值效果和科研贡献。

### 3.2 验证、记录与复现

在当前二次型和非线性回归上实际验证所提方案。检查实现与设计一致；记录目标曲线、计算成本及支持结论所需的辅助状态。不强制另做固定终止时间的步长细化或完整误差分析。

保存第 0 步、完整原始记录、失败前最后有效目标、实际接受步数、NaN/Inf、非正辅助值及失败原因。`Result.md` 给出相对路径的复现命令、配置与随机种子，链接本地原始结果和图。所有运行代码在己方目录内，不依赖原仓库运行入口。

明确列出已执行、未执行、失败及未解决事项。未完成的部分不能伪装为通过验收；原题缺少的跨种子统计、重复计时和状态轨迹，只有实际补充后才可作为新证据。所需最小材料及已知缺口见 Background §6；缺项不授权扩大访问。

## 4. 两份文档与写作验收

| 文件 | 必须呈现 |
| --- | --- |
| `Handoff/Design.md` | 可行方案、必要假设、简洁公式、严格辅助耗散证明及已知限制 |
| `Handoff/Result.md` | 实际实验设置、控制变量、预算、结果表与曲线、成本与失败、可复现命令、证据支持的判断 |
| `Handoff/fig/` | 两文档及其他 Markdown 使用的全部图片，均以相对路径引用 |

使用简洁语言，以数学表达式为主，结合表格与图。沿用 Background 已说明的 doc 风格，必要时只在允许的文件范围内参考。短句逐项说明，每句话都应让读者立即理解对象、条件或结论，避免长篇空泛叙述和阅读障碍。所有数学只使用 `$...$` 和 `$$...$$`。

验收优先级是实验效果高于文档写作，不新增数值权重。数学硬约束、真实执行与权限规则必须满足；文风不能弥补缺失的证明、结果或执行证据。

## 5. 违规扣分

任何违规情况均会被大幅扣分，包括但不限于：未说明理由而改变 ESAV 递推框架、擅自改变冻结的 SAV 递推框架、不满足无条件辅助能量耗散、干扰 main 或对方工作，以及违反目录或本地运行规定。允许有理由地提出另立名称的新方案，但须说明相对原式的改变、理由和依据，并完成所需证明与实验；这不授权修改冻结基线。不预设具体扣分数值。
