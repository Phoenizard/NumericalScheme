# 设计文档写作约定

## 正式算法设计

- 以数学表达式为主，按“定义与初始化 → 时间导数与梯度流 → 一阶离散 → 递推公式 → 耗散证明”组织。
- 展示必要的代入、近似和构造步骤，保持推导连续；说明修改的数学动机。
- 最终 scheme 明确初值、时间层与计算顺序，完整给出参数及辅助变量的更新。
- 写清必要假设、耗散对象和证明；依据论文时注明来源，区分原式与项目修改。

## Notes 与动机说明

- 核心是用浅显、有逻辑的语言把问题讲清楚。
- 从读者已知的问题出发，逐步解释为什么需要观察某个量、采取某项修改，以及得到什么结论。
- 按理解需要使用公式和简单例子，交代数值来源；不强求公式占主导，也不机械套用算法推导结构。

## 共同写作要求

- 简洁以降低阅读负担为准：删除重复说明，保留必要的逻辑连接。
- 沿用已有符号，不为缩短公式随意增加中间符号；向量加粗，矩阵大写加粗。
- 只解释读者自然产生的疑问，只在确需注意处强调；不反复声明未采用的方法或已明确的结论边界。
- 正文呈现最终内容，不混入修改经过、核查日志和对话记录；实验结果另放实验报告，个人 Notes 可独立保留。
- 尊重用户手动删改；要求原样抄写的段落保持原样，已删除的说明不重新加入。
